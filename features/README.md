# Признаки из календаря и истории

`01_feature_engineering.ipynb` читает дневные таблицы после исследования и создаёт одинаковую целевую таблицу для всех моделей. Полный ряд дней пары склад × артикул нужен, чтобы учитывать и дни без продаж. Первый день появления используется для истории; прогноз оценивается со следующего дня.

В [FEATURES.md](FEATURES.md) поддерживаем словарь всех 50 признаков: имя в коде, понятное название, расчёт, сущность и доступность. В `catalog.py` лежат те же русские названия для графиков и таблиц. При добавлении признака обновляем словарь, подпись и список в ноутбуке.

## Два набора для каждой модели

| Набор | Входы |
|---|---|
| Базовые поля | Склад, артикул, категория 1-го и 2-го уровней, характеристика — 5 категорий |
| С FE | Те же поля + 42 числовых признака и 3 явных сочетания категорий — 50 входов |

Календарь описывает дату и возраст пары. История пары — её прошлые продажи, средние и разброс. Остатки берём за вчера. Более общая история складывает продажи по складу или артикулу. Явные сочетания соединяют артикул со складом/днём недели и склад с днём недели.

Все окна заканчиваются вчера. Описание артикула используем только после первой известной продажи. Текущие продажи и остатки, технический `pair_id` и даты появления не подаются модели. Медианы, масштабы и словари категорий оцениваются только на обучении внутри training-ноутбуков.

Результат — одинаковые `train/valid/test.parquet` для обеих версий моделей, описание наборов в `feature_manifest.json` и справочные PNG/CSV в `data/artifacts/features/`. Исходные значения после этой перестройки не менялись: добавлены явное описание двух наборов и русские подписи.
