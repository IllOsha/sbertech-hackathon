# Прогноз продаж: SberTech hackathon

Исследуем продажи и остатки, создаём признаки из истории и сравниваем модели. Одна строка для прогноза — **день × склад × артикул**. Предварительная цель — предсказать число проданных единиц на следующий день по информации до конца вчерашнего дня.

В исходных данных 1,49 млн строк продаж и 6,15 млн строк остатков, 11 складов и 799 артикулов. Официальные описание задачи, горизонт прогноза и метрика пока не предоставлены: текущая постановка и оценки требуют сверки с условиями организаторов.

**Для первого знакомства:** [сущности и обзор данных](research/01_data_overview.ipynb) → [выводы исследования](research/findings.md) → [результаты моделей](training/results.md).

## Быстрый старт

Графики и выводы уже сохранены в ноутбуках: их можно читать на GitHub без установки Python и исходных данных. Для повторного расчёта:

```bash
git clone https://github.com/IllOsha/sbertech-hackathon.git
cd sbertech-hackathon
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ipykernel install --user --name sbertech --display-name "Python (sbertech)"
```

Текущий прогон выполнен на Python 3.14. Получите `hakaton.zip` у команды или организаторов и положите два CSV с исходными именами в `docs/datasets/`, как описано в [памятке](docs/datasets/README.md). Данные в репозиторий не включены; публичной ссылки на скачивание пока нет.

Запуск шести основных ноутбуков из корня проекта:

```bash
python scripts/run_notebooks.py --kernel sbertech
```

Для работы по ячейкам запустите `jupyter lab` и выберите ядро **Python (sbertech)**. Порядок одинаков для ручного и автоматического запуска:

| Шаг | Ноутбук | Что создаёт |
|---|---|---|
| 1 | [Обзор данных](research/01_data_overview.ipynb) | Дневные продажи и остатки, отчёт о качестве |
| 2 | [Признаки](features/01_feature_engineering.ipynb) | Общие выборки обучения, валидации и теста |
| 3 | [Линейная модель](training/01_linear.ipynb) | Метрики Ridge и простых правил, коэффициенты |


Скрипт сохраняет результаты ячеек в исходный `.ipynb`; повторный запуск обновляет также отчёты и графики. Обучение использует фиксированную выборку 600 тыс. строк; валидация и тест берутся целиком.

## Что сравниваем

**Базовые поля** — пять исходных категорий: склад, артикул, два уровня категории товара и характеристика. **FE** (feature engineering) — дополнительные признаки: календарь, прошлые продажи, вчерашние остатки, история склада/товара и явные сочетания категорий. Всего с FE — 50 входов; определения и момент их доступности записаны в [словаре](features/FEATURES.md).

Ridge, CatBoost, DCN и MLP обучаются в обеих версиях. Внутри пары одинаковы строки, настройки и функция потерь: так оцениваем пользу признаков. DCN — нейросеть с отдельной веткой взаимодействий; сравнение с MLP помогает оценить пользу этой ветки.

## Как проверяем качество

| Период | Даты | Назначение |
|---|---|---|
| Обучение | 2024-01-29 — 2026-06-05 | Обучение моделей и преобразований |
| Валидация | 2026-06-06 — 2026-07-03 | Выбор момента остановки |
| Тест | 2026-07-04 — 2026-07-31 | Оценка зафиксированной модели |

История каждый день обновляется фактическими продажами до вчера. Прогноз сразу на несколько недель от одной даты потребует другой проверки. Пропущенные продажи после появления пары считаем нулём. Несколько записей остатков на одном ключе описываем средним, минимумом, максимумом и числом записей; доступность этих полей к моменту прогноза нужно уточнить у организаторов.

Главный локальный ориентир — **MAE**, средняя абсолютная ошибка в штуках. Также смотрим WAPE, RMSE и смещение общего объёма. CatBoost с FE получил MAE около **0,2865** против **0,3933** на базовых полях, но недопрогнозировал общий объём примерно на 40%. Выбор итоговой модели зависит от официальной метрики. Полные результаты — в [training/results.md](training/results.md).

## Дополнительные исследования

Эти ноутбуки запускаются отдельно и не входят в основные шесть шагов:

| Ноутбук | Что проверяет | Что выполнить заранее | Выводы |
|---|---|---|---|
| [02_trics](research/02_trics.ipynb) | Длинную историю, вес свежих данных, двухэтапные модели, округление и смеси | Основную итерацию | [Отчёт](research/tricks_results.md) |
| [03_time_analysis](research/03_time_analysis.ipynb) | Рост и состав пар, STL/MSTL, недельную/годовую сезонность, сходство рядов, прогноз на 28 дней | Обзор данных и построение признаков | [Отчёт](research/time_analysis_results.md) |

```bash
python scripts/run_notebooks.py research/02_trics.ipynb --kernel sbertech
python scripts/run_notebooks.py research/03_time_analysis.ipynb --kernel sbertech
```

В `02_trics` настройки выбираются на первой половине июня и подтверждаются на второй. Июль уже просмотрен в ходе исследований: он больше не является независимым финальным тестом для новых гипотез. Анализ времени ограничен обучением до 2026-06-05; его метрики агрегированных рядов нельзя напрямую сравнивать с ошибкой на отдельную пару склад × артикул.

## Что храним в Git

| В репозитории | Только локально | Почему |
|---|---|---|
| Код, зависимости, документация | `.venv/`, кеши, `.env*` | Окружение пересоздаётся, локальные настройки не публикуются |
| Выполненные `.ipynb`, PNG и небольшие CSV/JSON в `data/artifacts/` | Исходные CSV в `docs/datasets/`, архив `hakaton.zip` | Результаты доступны коллегам без загрузки тяжёлых исходников |
| Описания признаков и параметры экспериментов | `data/processed/`, `data/models/` | Таблицы, прогнозы и веса пересоздаются ноутбуками |

Правила заданы в [.gitignore](.gitignore). При добавлении нового эксперимента обновляйте словарь признаков, README раздела и сохраняйте компактный итог в `data/artifacts/`.
